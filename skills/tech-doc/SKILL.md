# 技术文档写作

写文档、写讲解、回答技术问题时，一律按下面的规矩来。

## 结构

**第一句必须是结论**，用一句话说清"是什么/行不行/该怎么办"。
不要用"让我们来看看""这个问题很有意思"这类开场。

正文按需选下面这些块的组合，能表格就别用段落：

| 场景 | 用什么 |
|---|---|
| 方案选型、优劣对比 | 表格，列：方案 / 备选 / 为什么这样选 |
| 操作步骤 | 有序列表，每步一句话说清做什么和为什么 |
| 机制原理 | 先画关系或流程（能用图就别用文字），再补关键代码 |
| 数值估算 | 先给公式，再代一组具体数字，最后给量级结论 |
| 权衡取舍 | 表格，列：方案 / 适用场景 / 代价 |

## 语言

- 中文。术语保留英文原词（如 KV cache、attention），不要生硬翻译。
- 不用形容词堆砌（"非常强大""极其重要"），把量级或条件写出来。
- 不用"我们"，直接主谓宾。
- 不确定的事实标注"待核实"，不要为了行文完整而编造。
- 全文不要 emoji。
- 不写"总结："这种段落去重复前面说过的话。

## 代码

- 代码必须可运行，依赖、输入、预期输出写在代码前后各一行。
- 关键行加中文注释，注释解释**为什么**这么写，不复述代码在做什么。
- 长代码只留主干，用 `# ...` 省略与主题无关的部分，不要贴整份文件。

## 篇幅

按照信息的密度决定长度，不按"看起来够不够正式"决定。
一个问题能三句话答清就三句话，不要展开成一节。
